# 2026-10-28 检查与菜单响应优化（v2.8.12）

基于 v2.8.11 检查安装入口、依赖与端口预检、菜单及账户摘要、节点编辑、证书、核心和管理脚本更新、备份恢复、防火墙/BBR、WARP、Argo、订阅与用户配额。结合源码检查、静态检查和隔离回归；未登录或修改用户生产 VPS。

| 发现的问题 | 修复与验证 |
| --- | --- |
| 启动时逐个查询五项服务，慢系统查询可累加且没有等待上限 | 合并服务查询及网卡查询；可选系统查询正常超时 2 秒，超时后最多再等待 1 秒强制结束，失败显示未知，不误报停止 |
| 主菜单账户摘要等待配额后台任务的独占锁 | 只读摘要使用原子替换的数据快照；真实独占锁占用时仍可返回；配额修改和计量继续使用锁 |
| 内容未变仍重写快捷命令和脚本副本 | 比较内容及权限；未变时保留 inode/mtime，权限错误仍修复，原文件发送工具与非托管文件继续受保护 |
| 证书到期查询可能等待不返回 | OpenSSL 查询限时 2 秒，保留证书不可读/过期提醒 |
| 通用预检通过后，追加协议和修改端口的内部检查仍可能把 TCP TIME_WAIT 误报为占用 | TCP 探测使用 SO_REUSEADDR，UDP 保持独占；真实关闭连接后追加 Reality、编辑 TCP 端口通过，实际监听占用仍被拒绝 |

受控性能比较：每项服务查询模拟等待 200ms，启动信息从 **1.091 秒降至 0.271 秒**。这是同一测试机的比较，不能保证生产 VPS 的固定响应时间。没有新增常驻服务或修改节点转发方式。

本地执行构建一致性、所有 Bash 文件语法、ShellCheck、Python 编译、自检及完整回归，使用 sing-box 1.14.3、Mihomo 和 HAProxy 实际二进制。发行版兼容性、GNU timeout 实测与用户容量基准由 Ubuntu 24.04、Debian 11/12/13 的发布检查继续验证。

测试覆盖失败时回退、已有文件归属与软链接、重复安装、节点参数保留、TCP/UDP 冲突、TLS/Reality、WARP 分流与出口验证、订阅鉴权、账户额度及防火墙操作。没有在这些检查中观察到新的未解决失败；这不等于证明所有 VPS 环境没有其他问题。真实公网入站、云安全组、CDN、服务商线路与账号解锁仍需在部署环境检查。

实际内存与负载可通过 **d → 7** 查看。用户配额功能为每位用户运行独立核心；启用的组件和连接数会影响资源，菜单响应优化不代表转发吞吐提升。
